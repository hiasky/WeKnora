# 知识网络与引导式学习：使用指南

## 一、使用前准备

该原型依赖 WeKnora 已有的长期记忆和 Wiki 功能。使用前请确认：

1. 管理员已在工作空间设置中开启“长期记忆”；
2. 当前用户已在“我的记忆”中开启长期记忆；
3. 智能体没有关闭长期记忆；
4. 目标知识库已在“编辑知识库 → 索引策略”中开启 Wiki；
5. 知识库中的文档已经完成解析和 Wiki 生成。

长期记忆或 Wiki 未开启时，普通 Wiki 浏览仍可使用，但不会产生个人掌握度覆盖层。

## 二、快速体验

### 1. 准备知识库

创建或打开一个知识库，上传至少两篇内容互相关联的文档。开启 Wiki 后等待知识处理状态变为完成，然后确认“Wiki”和“图谱”页签中已经出现页面与连线。

### 2. 产生学习证据

使用绑定该知识库的智能体进行问答，例如连续询问：

```text
请根据知识库解释 RAG 的基本流程，并给出来源。
向量检索和关键词检索分别解决什么问题？
请结合资料比较两种方法。
```

只有回答实际采用的来源文档才会增加证据计数。为了越过现有“常用资料”阈值，建议至少进行两轮能引用同一文档的有效问答。

### 3. 查看知识网络

进入“知识库 → 图谱”。个人学习覆盖层会叠加在原有 Wiki 图谱上：

- 节点颜色：页面类型，含实体、概念、摘要、综合等；
- 节点明暗：掌握度越高，节点越实；
- 蓝色实线外环：该节点来源于用户反复使用的资料；
- 橙色虚线外环：建议下一步学习；
- 鼠标悬停：显示掌握度、引用次数，或者推荐原因。

点击橙色推荐节点即可打开页面；也可以继续展开其相邻节点。

## 三、掌握度如何计算

当前原型使用确定性规则：

```text
节点证据次数 = 该 Wiki 页面全部来源文档的回答引用次数之和
掌握度 = min(100, 节点证据次数 × 10)
```

例如，一页内容来自两篇文档，这两篇文档分别在回答中被采用 2 次和 3 次，则该节点证据次数为 5，掌握度为 50。

该分数表示“有证据的使用熟悉度”，不等同于考试成绩或能力认证。模型不会主观判断用户是否掌握。

## 四、推荐如何产生

系统从用户已经有掌握证据的节点向外寻找一跳邻居。满足以下条件的页面会被推荐：

1. 当前页面掌握度为 0；
2. 它与至少一个已有掌握证据的页面直接相连。

悬停时会显示相连的已掌握页面名称。当前 Wiki 链接没有严格的先修语义，因此推荐表示“适合沿当前主题继续探索”，不是强制课程顺序。

## 五、查看、导出和删除画像

以下接口均只访问当前登录用户的画像，不能通过参数查看其他用户。

在“知识库 → 图谱”左上角图例的操作区，可以直接点击“导出学习画像”或“删除学习画像”。删除操作会先显示二次确认，完成后图谱自动刷新。

### 查看

```http
GET /api/v1/knowledgebase/{kb_id}/wiki/learning-profile
```

返回节点掌握度、证据次数、推荐标记、推荐理由以及汇总数量。

### 导出

```http
GET /api/v1/knowledgebase/{kb_id}/wiki/learning-profile/export
```

浏览器会下载 `weknora-learning-profile.json`。导出的分数是当前证据和 Wiki 网络的即时计算结果。

### 删除

```http
DELETE /api/v1/knowledgebase/{kb_id}/wiki/learning-profile
```

删除内容仅包括当前用户在该知识库中的文档引用计数。不会删除：

- 知识库文档；
- Wiki 页面或图谱；
- 当前用户在其他知识库中的画像；
- 其他用户的画像。

删除后刷新图谱，相关节点的个人掌握度和推荐覆盖层会消失。后续继续进行带来源的问答时，系统会从零重新累计。

## 六、本地运行与验证

按照 WeKnora 原有开发方式启动前后端。原型不新增数据库迁移或外部服务。

运行后端测试：

```bash
go test ./internal/application/service ./internal/application/service/memory ./internal/handler ./internal/router \
  -run 'TestComputeGraphSubset|TestMasteryScore|Wiki|Memory|Document' -count=1
```

运行前端检查：

```bash
cd frontend
npm run type-check
npm run check-i18n
```

如果完整前端类型检查报告 `@xterm/xterm` 或 `@xterm/addon-fit` 缺失，需要先补齐仓库的前端依赖；这与学习覆盖层本身无关。

## 七、演示建议

演示时准备两个账号访问同一知识库：

1. 账号 A 连续询问主题 A，并产生相同文档的多次引用；
2. 账号 B 询问主题 B；
3. 两个账号分别打开同一张 Wiki 图谱；
4. 展示相同知识网络上的不同点亮区域和不同推荐；
5. 导出账号 A 的画像；
6. 删除账号 A 在该知识库中的画像并刷新；
7. 确认账号 B 的覆盖层不受影响。

这组流程同时演示知识映射、可解释度量、引导推荐、可视化和租户/用户隔离。
